## Design Context

### Users

**Primary goal: get hired.** Visitors are recruiters, hiring managers, and engineers doing first-pass screens — often on a shared link or search result, mostly desktop, in a professional evaluation mindset. They need to **trust you quickly** (credible engineer, clear story) and **scan fast** (role, stack, proof). The site must survive a 30-second skim *and* reward a 5-minute deep dive for anyone who advances you.

Secondary: fellow developers and potential collaborators evaluating whether you’re interesting to work with — still professional, not casual social traffic.

### Brand Personality

**Futuristic · Creative · Hacker**

The interface should feel like something built by someone who understands systems at a low level and chose to make something beautiful with that knowledge. Not “hacker” as edgy or aggressive — hacker as *resourceful, curious, building things others haven’t thought of*. Not “futuristic” as generic sci-fi — futuristic as *a plausible near-future operating system that could actually exist*. Creative means unexpected choices and craft, not decoration for its own sake.

**First-impression emotional target:** **confidence** — visitors should read “serious engineer, trustworthy, in control of the craft,” not novelty for novelty’s sake.

### Aesthetic Direction

**xiaoOS × Wu Wei — refined command-center, single-scroll editorial home.** Keep the OS / HUD concept but push it toward something more *designed* and less *themed*: a **custom-built tool**, not surveillance cosplay or movie chrome.

- **Theme:** Dark by default (`color-scheme: dark`, warm near-black base). Light mode (`.light-mode`) exists in tokens as a deliberate alternate, not the primary story.
- **References (spirit, not copy):** Bloomberg Terminal density; the quiet confidence of a well-designed CLI; mission-control UIs that prioritize information over decoration.
- **Anti-references:** Generic developer portfolios (hero + identical project cards + timeline). AI-default aesthetics (gradient text, glass-everywhere, purple–blue neon). “Gamer” energy (noisy chrome, RGB-for-RGB’s sake). Award-site spectacle that hides substance.

**Impeccable alignment:** No gradient text; no fat colored side-stripe “accent” borders on cards/lists; accents stay **rare** and semantic (cyan for emphasis / active / links).

### Design Principles

1. **Hiring-first clarity.** Above all, make role, skills, and proof scannable. Wow-factor supports credibility; it never replaces signal.

2. **Functional beauty.** Every visual element should earn its place — status, hierarchy, or OS metaphor. Decorative bits should read as *system details*, not ornaments.

3. **Plausible fiction.** xiaoOS should feel like it *could* be real software: consistent components and copy that sounds like an OS, not a film.

4. **Information density over empty space.** HUD-style density is fine when it carries real information — never clutter.

5. **Refined restraint.** Cyan accent is **one** chromatic voice — interaction, status, emphasis — not wallpaper.

6. **Earn the wow.** Memorable through coherence and craft — boot flows, transitions, typography — not one-off gimmicks.

## Implemented design system (source: `src/styles/main.css` + templates)

This section is the **code-truth** summary. New UI should extend these tokens and patterns before inventing parallel systems.

### CSS tokens (`:root`)

| Token | Role |
|--------|------|
| `--xw-bg`, `--xw-bg-elev`, `--xw-bg-soft` | Warm dark surfaces (near-black stack) |
| `--xw-ink`, `--xw-ink-muted`, `--xw-ink-faint` | Body → secondary → labels/meta |
| `--xw-hairline`, `--xw-hairline-hi` | 1px hairline borders (warm tint) |
| `--xw-accent`, `--xw-accent-ink` | Single cyan accent + text on cyan chips |
| `--xw-display` | IBM Plex Sans (headings / UI) |
| `--xw-mono` | IBM Plex Mono (caps labels, rail, code-adjacent UI) |
| `--xw-fs-*`, `--xw-tracking-caps` | Modular scale; wide caps tracking for labels |
| `--xw-topbar-h`, `--xw-gutter`, `--xw-section-pad` | Layout rails; body gets `padding-top: var(--xw-topbar-h)` |
| `--z-*` | Stacking: content → topbar → mobile nav → modal → boot overlay |

Legacy aliases (`--nexus-*`, `--color-*`, etc.) remain for older class names; **prefer `--xw-*`** for new work.

### Shell & navigation

- **Top bar:** `.xw-topbar` — brand lockup **xiao** + **OS**, primary nav (`#xw-primary-nav`), live clock (`#xw-clock`), mobile toggle.
- **Nav order (home anchors):** About → Projects → Experience → Contact → All projects → Resume (matches section order on the page).
- **Mobile:** `.xw-mobile-nav` overlay; `body.xw-mobile-nav-lock` when open.
- **Footer strip:** `.xw-status` — name/title, year, page label.

### Home layout (Wu Wei)

- **Single scroll:** `section[data-xw-section]` — `about` → `projects` → `experience` → `contact`.
- **Scroll-spy:** TS (`src/home/topbar.ts`) drives active state from scroll position (activation line below top bar), not “largest intersection ratio.”
- **Section index rail:** `.xw-section-rail` (hidden `<900px`) — numbered caps-mono list with labels (e.g. Projects, Experience); active state via `data-xw-active` / `data-xw-rail`.
- **Reveals:** `[data-xw-reveal]` — entrance motion; can reset when leaving viewport (`src/home/revealer.ts`) so scroll direction doesn’t leave stale state.

### Typography & copy patterns

- **Display:** Large editorial hero (`.xw-display`, fluid `clamp` on hero size).
- **Labels:** `.xw-caps`, `.xw-index` — mono, uppercase, tracked; section numbers **01–04** align with rail.
- **No** gradient text; **no** decorative left-border stripes on cards per impeccable bans.

### Motion & boot

- **Boot:** `#startup-animation` + `StartupAnimation` — preserve as the default intro; refactor tokens/copy around it, don’t delete the sequence wholesale.
- **GSAP / transitions:** Use for orchestrated moments; prefer transform/opacity for performance.

### Accessibility & motion (actual behavior)

- **Target:** Semantic regions, focusable controls, readable contrast on type.
- **Heavy motion:** Prefer respecting `prefers-reduced-motion` for **new** disruptive animation; existing paths may vary — when in doubt, test and align with principles above.

### Technical constraints

- **Stack:** Go templates, vanilla TypeScript, Tailwind + PostCSS, esbuild bundle to `static/js/main.js`.
- **Don’t** introduce a new framework for one-off UI without an explicit project decision.
